# Миграция конфигов на OpenCode v2

Дата: 2026-10-24. Затрагивает `config/opencode.json` и `profiles/*/opencode.jsonc`.

## Что переведено на новые ключи

| Было (v1) | Стало (v2) | Комментарий |
|---|---|---|
| `command` | `commands` | полностью эквивалентно |
| `mcp: { name: {...} }` | `mcp.servers: { name: {...} }` | заодно `enabled` → `disabled` (инверсия) |

## Что осознанно оставлено в legacy-виде

Схема v2 (`https://opencode.ai/config.json`) помечает эти ключи как `deprecated`,
но принимает их. Перевести их без потери функциональности нельзя:

- **`provider`** (не `providers`) — v2 `providers.*` не умеет задавать
  `options.baseURL` и `options.apiKey`, а также `models.*.interleaved`.
  SourceCraft и LM Studio используют именно эти поля.
- **`agent`** (не `agents`) — v2 `agents.*` не поддерживает `temperature`,
  `prompt` и `permission` (вместо последнего — `permissions` с другой формой
  правил). В профилях 39 агентов используют все три поля.
- **`permission`** (не `permissions`) — форма `permission` (`bash: ask`,
  `skill: {"*": deny, ...}`) не эквивалентна списку правил v2; миграция
  изменила бы семантику доступа.
- **`small_model`** — остаётся, т.к. `model` в v2 принимает объект, но
  legacy-строка работает и валидируется схемой.

## opencode-pty удалён

Плагин `opencode-pty` не загружается в OpenCode 2.x: загрузчик не поддерживает subpath-спецификаторы
(`opencode-pty/v2` трактуется как отдельный пакет и падает с `NpmInstallFailedError`), а корневой
entrypoint экспортирует v1-плагин и отвергается схемой v2. Пакет удалён из `config/opencode.json`,
`config/package.json` и профилей sec/ot. При возврате нужен upstream-фикс или локальный шим.


## envsitter-guard (исключён)

Плагин `envsitter-guard@0.1.0` удалён из конфигурации 2026-10-25.
Причина: при старте он сканирует все `.env*` в домашнем каталоге и падает на
`~/.projects/infrastructure/.envrc` (`Invalid dotenv file: L2: Missing = in assignment`),
после чего блокирует регистрацию инструментов — недоступными становятся shell/read/write.

Повторное включение возможно только с ограничением области сканирования
(каталоги проектов, без `$HOME` целиком) и после проверки на `.envrc`.

## Профили в v2: обязательный `--standalone` (2026-10-25)

В OpenCode v2 конфигурацией владеет фоновый сервис, а не TUI-клиент. Поэтому
`OPENCODE_CONFIG=.../opencode-<profile>/opencode.json opencode` **не переключает
профиль**, если общий сервис уже запущен: клиент подключается к нему, и
применяется default-конфиг (`~/.config/opencode/opencode.json`).

Симптом: `oc-net` открывается, но в статус-баре 0 MCP вместо 4.

Решение: запускать профиль с приватным сервером — `opencode --standalone`.
Так делают `scripts/ocp` и алиасы `oc-dev`/`oc-infra`/`oc-net`/`oc-sec`/`oc-ot`/`oc-mgnt`
(`setup.sh`), а также функции PowerShell в `setup.ps1`. Проверка:

Дополнительно все они передают `--continue`: запуск продолжает последнюю сессию
проекта вместо создания новой. `ocp` добавляет флаг сам, если пользователь не
указал `-c`/`--continue`/`-s`/`--session`. Новая сессия — `leader+n` в TUI.

```bash
OPENCODE_CONFIG=~/.config/opencode-net/opencode.json opencode --standalone
# в статус-баре должно быть 4 MCP
```

## Удалённые неиспользуемые артефакты (2026-10-25)

При аудите удалены файлы, которые не читаются ни скриптами, ни тестами, ни деплоем:

- `config/opencode.jsonc` — заглушка `// Generated by opencode-synced` (default живёт в `config/opencode.json`);
- `config/skills-lock.json` — legacy-реестр единственного скилла `grill-me`;
- `config/prompts/personas/` — 6 файлов-дублей (персоны лежат в `prompts/personas/` и копируются в профили);
- `config/plugins/` — стандартный каталог локальных плагинов (сейчас `profile-badge`).

Единственный источник персон — `prompts/personas/` (копии в `profiles/<profile>/prompts/personas/`),
скиллов — `config/skills/`.
