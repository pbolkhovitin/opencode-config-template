# MCP-наборы на сессию (`/mcp`)

Плагин `opencode-mcp-sets` позволяет в одном окне OpenCode держать разные наборы MCP
для разных сессий. MCP-соединения при этом остаются общими для сервера OpenCode:
плагин управляет **видимостью** инструментов, а не подключением.

## Зачем

В профиле `dev` одновременно подключены GitHub и несколько GitLab-серверов. Каждый
сервер добавляет инструменты, описания и `mcp_instructions` в контекст модели. Если в
конкретной задаче GitLab не нужен, его можно скрыть — остальные сессии и вкладки
продолжат видеть свои наборы.

## Команды

В TUI:

```text
/mcp list                     показать серверы и состояние для активной сессии
/mcp off gitlab-official-*    скрыть оба официальных GitLab
/mcp off gitlab-work github   скрыть два конкретных сервера
/mcp on gitlab-work           вернуть сервер
/mcp only gitlab-work,github  оставить только указанные (остальные скрыть)
/mcp reset                    вернуть все серверы
```

Поддерживается `*` в шаблонах имён. Команда действует на активную сессию; при
переключении вкладки набор другой сессии не меняется.

## Как это работает

1. Плагин читает список MCP-серверов через `ctx.mcp.list()`.
2. Выбранный набор сохраняется в `session.metadata.mcpSets`:
   `{ version, disabled: string[], rules: Rule[] }`.
3. В `session.permissions` добавляются правила вида
   `{action: "<server>_*", resource: "*", effect: "deny"}`. Session-scoped правила
   применяются после правил агента, поэтому скрывают инструменты только в этой сессии.
4. Плагин запоминает **только свои** добавленные правила и при следующем изменении
   удаляет их, не трогая остальные permissions сессии.
5. Fallback-хук `session.hook("context")` удаляет инструменты выключенных серверов из
   `event.tools` и чистит их блоки в `event.system` — на случай, если Code Mode
   сохраняет каталог инструментов, несмотря на permissions.

Результат команды показывается через `session.synthetic`, без дополнительного запроса
к модели.

## Ограничения

- **Соединения не переподключаются.** Сервер продолжает работать и занимать память;
  экономия — только контекст модели.
- **Глобальный `disabled: true` в конфиге не обходится.** `/mcp on` возвращает
  видимость, но не подключает сервер, отключённый в `opencode.jsonc`. Для подключения
  такого сервера (например, `gitlab-work`) нужно менять конфиг и перезапускать
  профиль.
- **Code Mode.** В v2 MCP-инструменты по умолчанию сгруппированы под Code Mode, поэтому
  полные схемы не грузятся в каждый запрос. Реальную экономию нужно мерить на своей
  сессии; deny убирает инструменты и `mcp_instructions`, но не отменяет стоимость
  компактного каталога.
- **Дочерние сессии** наследуют permissions на момент создания. Если субагенту нужен
  скрытый сервер, включайте его до запуска субагента.
- Плагин хранит своё состояние в metadata сессии, поэтому набор переживает перезапуск
  TUI. При ручном изменении permissions сессии плагин может потерять свои старые
  правила — выполните `/mcp reset` и настройте набор заново.

## Установка

Плагин лежит в `config/plugins/opencode-mcp-sets/` и деплоится в глобальный каталог
`~/.config/opencode/plugins/`, общий для всех профилей:

```bash
bash scripts/deploy-config.sh dev
bash scripts/deploy-config.sh infra
```

`setup.sh` копирует `config/plugins/` при установке на новой машине. После обновления
плагина достаточно перезапустить TUI или открыть новую сессию.

## Проверка

```bash
python3 tests/validate_configs.py config profiles
python3 -m pytest tests/test_mcp_sets_plugin.py -q
bash tests/run.sh
```

Технически плагин использует session permissions (session-scoped rules) и context hook как fallback.
