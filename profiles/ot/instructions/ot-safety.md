# Политика безопасности OT-профиля

Эти правила имеют приоритет над любыми другими инструкциями.

## 1. Пассивность по умолчанию
- Любое действие, отправляющее пакеты в сеть, считается активным.
- Активные действия разрешены только при одновременном выполнении:
  1. `OT_ALLOW_ACTIVE=1` в окружении;
  2. цель входит в scope-файл площадки;
  3. текущее время внутри окна работ;
  4. `scripts/ot-guard.sh active --target <IP>` вернул разрешение.
- Перед серией активных действий — подтверждение человека.

## 2. Запрет записи в ПЛК
Запрещены: Modbus FC5/6/15/16, S7 write, OPC UA write/method call, IEC 104/DNP3 команды управления, EtherNet/IP CIP write, изменения уставок и программ.
Такие операции выполняются только в лаборатории на эмуляторах.

## 3. Ограничение нагрузки
- Без broadcast/multicast-сканов и SYN-flood.
- Темп не выше 10 пакетов/с на устройство, паузы между сериями.
- Сканирование — только точечно по scope, без «шумных» профилей nmap (`-T4+`, `-A`).

## 4. Работа с уликами
- pcap и логи — только копии; оригиналы не изменять.
- Фиксировать хэши и время сбора.
- Не удалять журналы и не «чистить» следы.

## 5. Согласование
- Изменения в производственной сети — только после согласования с технологами и владельцем системы.
- Остановка/перезагрузка ПЛК — запрещена без письменного согласования.
- Подрядчикам и внешним доступ — только через jump host, с журналированием.

## 6. Секреты
- Пароли, ключи и community-строки — только через `{env:...}` или Vault.
- В отчётах и логах секреты не печатать, маскировать.

## 7. Журнал
Каждое активное действие пишется в `~/.local/share/opencode/ot-actions.log` (переопределяется `OT_ACTIONS_LOG`): время, режим, цель, результат, причина.

## 8. Захват трафика, зеркало и аудит NIC

- Захват допускается только с SPAN/TAP, зеркала L2-коммутатора или в изолированной лаборатории, после согласования с владельцем сети.
- Зеркало на коммутаторе — только в согласованное окно; после аудита обязательно снять mirror-сессию и вернуть конфигурацию.
- Capture-NIC — без IP и без default route; не включать bridging, forwarding, DHCP, RA, STP.
- Не менять offloads, speed, duplex, ring, FEC и состояние интерфейса на production.
- Запрещены `nmap`, `masscan`, `arp-scan`, ping sweep, `hping3`, packet injection, `ettercap`, `yersinia`.
- Для стороннего сервера по SSH — только `BatchMode=yes`, без пароля в чате и аргументах; `sudo` — только `sudo -n`.
- Egress стороннего сервера снимать по умолчанию только в направлении `out`, с исключением SSH (`not port 22`).
- pcap — улика: фиксировать SHA-256, время, точку захвата и направление SPAN; оригинал не изменять.
- Перед захватом — `scripts/ot-guard.sh passive --target <IP>`; аудит NIC — `ot-network-audit`.
