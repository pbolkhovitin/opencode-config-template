# Net Profile — Сети, маршрутизация, firewall

Правила безопасности для сетевого профиля. Дополняют `AGENTS.md`.

## Режим по умолчанию

- **Read-only first.** Сначала собирай факты: конфигурация, топология, логи, счётчики, pcap.
- Любое изменение конфигурации оборудования — только после явного подтверждения пользователя.
- Перед изменением: сохрани backup конфигурации (export/show running-config) и зафиксируй rollback-план.

## Удалённый доступ

- На MikroTik используй `safe mode`; при работе через SSH — таймер отката (`/system scheduler`) или out-of-band доступ.
- Не меняй маршрутизацию/firewall на устройстве, к которому нет второго пути доступа.
- Пароли и ключи — только из Vault (`agent-vault`), никогда в чат и не в конфиг репозитория.

## Активные действия

- Сканирование, брутфорс, инъекция трафика — только в согласованном scope и окне.
- По умолчанию — пассивный анализ (pcap, логи, SNMP-poll).
- Для тестов на реальном оборудовании — сначала лаборатория/эмуляция (containerlab, GNS3, EVE-NG).

### Активное сканирование

- Письменный scope: CIDR/хосты, порты, протоколы, разрешённые техники, окно, контактное лицо и stop conditions.
- Никогда не сканировать OT/ICS, АСУ ТП, safety-системы и чужие сети без письменного разрешения. Для OT — только пассивный `ot-network-audit`.
- Начинать с discovery, затем top-ports, затем точечные сервисы; не запускать full-port и `--script vuln` на production без согласования.
- Rate limit: `nmap --max-rate 500`, `masscan --rate 1000`; на слабых каналах — ниже.
- Запрещены spoofing, ARP poisoning, MITM, flood/DoS и инъекция пакетов в production.
- `ettercap` и `yersinia` — только лаборатория, в профиль `net` не входят.
- Логировать команду, время, источник, цель, rate и файл результата.
- Немедленно остановиться при потере пакетов, росте CPU/очередей, flap-ах маршрутизации, алертах IDS, жалобах эксплуатации или широковещательном шторме.
- Инструменты и безопасные примеры — скилл `active-network-recon`.

## Гигиена изменений

- Одно изменение — одна причина; не смешивай обновление прошивки и правку правил.
- Проверяй результат по счётчикам/логам, а не только по коду возврата команды.
- Документируй схему адресации и матрицу доступа в репозитории проекта.
