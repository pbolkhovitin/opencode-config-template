# Политика безопасности

## Поддерживаемые версии

Актуальной считается ветка `main`. Исправления безопасности выходят в неё;
отдельные LTS-ветки не поддерживаются.

## Как сообщить об уязвимости

**Не открывайте публичный issue.** Используйте приватный канал GitHub:

1. Откройте вкладку **Security** репозитория.
2. Выберите **Report a vulnerability** (GitHub Security Advisories).
3. Опишите проблему: затронутые файлы, сценарий эксплуатации, версия
   OpenCode/ОС, минимальный воспроизводимый пример.

Если приватный отчёт недоступен, свяжитесь с мейнтейнером через его профиль
GitHub и попросите приватный канал. Не публикуйте детали до исправления.

Мы постараемся подтвердить получение в течение 72 часов и согласовать срок
раскрытия после выпуска исправления.

## Область действия

В области:

- `setup.sh`, `setup.ps1`, `scripts/`;
- конфигурации профилей и проектный генератор;
- плагины в `config/plugins/`;
- обработка секретов, путей и временных файлов.

Вне области:

- уязвимости самого OpenCode — сообщайте в
  [opencode](https://github.com/anomalyco/opencode/security);
- уязвимости сторонних MCP-серверов и npm-пакетов — их авторам;
- конфигурация, изменённая пользователем после установки.

## Секреты

- В репозитории не должно быть токенов, паролей, ключей и cookies.
- Секреты передаются через `{env:...}` или HashiCorp Vault
  (скилл `agent-vault`), не через конфиги.
- При подозрении на утечку: отзовите секрет у провайдера, затем сообщите
  приватно. Удаления файла из git недостаточно — история сохраняется.

## Проверки

В CI запускаются схема конфигов, тесты гигиены репозитория и gitleaks.
Локально:

```bash
python3 tests/validate_configs.py config profiles
python3 -m pytest tests -q
```
